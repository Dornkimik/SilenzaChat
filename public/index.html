Privacy & encryption

      
Are all my messages end-to-end encrypted?
Private-chat text, attachments, captions, and mentions are encrypted in your browser and decrypted in the participants’ browsers. Temporary user-created rooms also encrypt text, attachments, captions, replies, and mentions for their current members. Main public-room messages are not end-to-end encrypted: visitors and the server can read them. Check the encryption status before sharing something personal.

Can the server or an admin read my private chats?
With the app running as designed, the server receives encrypted private messages without the secret keys needed to read them. Admin access does not unlock other people’s private conversations.
This depends on trusting the app delivered to your browser. Someone controlling the website could change its code to capture messages or keys. A compromised device or browser extension could also expose them.

      
What can the server still see?
The server can see aliases, who is talking to whom, connection IP addresses, message times, encrypted data sizes, and which messages are replies or have attachments. Encryption protects the contents of private messages; it does not hide all activity.

      
Am I completely anonymous?
You do not need an account, email address, or real name. Guests use random aliases; account holders use their chosen usernames. That does not make you untraceable: the server handles your connection, and the hosting provider may keep logs that include IP addresses. What you write, or show in a photo or video, can also identify you.

      
What does “Verify identity” do?
In a private chat, choose Verify identity and compare the entire code with the other person in person, over a call, or through another trusted channel. Both screens should match. Only then choose The codes match.
The browser remembers the first encryption key it sees for that session. Comparing codes helps detect a substituted key; comparing them only in this chat is not an independent check. A changed key blocks private communication. Verification confirms the key you compared, not someone’s real-world identity from their alias.

      
Is encryption a guarantee that nothing can go wrong?
No. A recipient can copy or share what you send, and encryption cannot protect a compromised device or a modified website. This chat does not provide forward secrecy: someone who steals your browser’s private key could decrypt previously captured encrypted messages for that identity.
The chat’s encryption integration has not had an independent security audit. Avoid sharing information whose exposure would put you at risk.

    

    

      
Attachments & message history

      
Does my attachment get uploaded to the server?
An encrypted version does. For photos, GIFs, videos and audio clips, your browser first removes hidden file metadata, such as location, camera or phone model, capture time and editing software. It rewrites only the file’s container and never redraws the picture, so no canvas is used. The original filename is not sent. The encrypted size is rounded up, so the server learns only an approximate size. The server holds the encrypted bytes temporarily in memory; the app does not write attachment files to disk.
Other files, such as PDFs or documents, are encrypted together with their name but otherwise sent unchanged: details stored inside them, like an author name, are not removed. The preview tells you which applies before you send.
The attachment key is shared inside an encrypted message to each recipient. The recipient’s browser downloads and decrypts it locally. Removing metadata does not hide personal information visible or audible in the content itself.

      
How long do attachments and messages stay available?
Announcements are saved until an admin removes them and survive server restarts. In other conversations, only the latest 100 messages are kept in server memory. They disappear when the server restarts. Sessions expire after 24 hours offline; private history expires after 24 hours without a message change, even if participants stay online. Private storage limits can prevent new sends or edits until space is freed.
Sent attachments expire within 24 hours of upload; the host can set a shorter lifetime. Attachments also disappear when their message is deleted or leaves recent history, either participant is banned or their session expires, or the server restarts. Unsent uploads expire within 10 minutes. This is a temporary chat, not a backup or permanent inbox.

      
Can I edit a message I sent?
Choose Edit on your own message, change the text or caption, and save. The message shows an edited label and updates for other participants. Attachments stay the same. Private and temporary-room edits remain encrypted; editing an older room message does not reveal it to new members. Deleted or expired messages cannot be edited.

      
Can I delete a message I sent?
Yes. Choose Delete on your own public or private message. It is removed from the conversation for everyone, along with any attachment. Replies show that the original message was removed. You do not need admin access.
Deletion cannot erase screenshots, downloads, or copies someone has already made. Automatic expiry has the same limit.

      
Can anyone open a link to my attachment?
The app does not create public attachment links. Downloads require an authorized browser session belonging to a participant, and the downloaded bytes are still encrypted. Your recipient can nevertheless save the decrypted file or share a copy.

      
Can someone receive a private message while offline?
Yes, if they have already opened SilenzaChat and set up their browser’s encryption identity. They can read it when they return while their session and recent message history are still available. Attachments must also be within their expiry period. A server restart clears waiting messages and attachments.

    

    

      
Using SilenzaChat
Do I need an account?
No. Choose Continue as guest for a random name, or create an account with only a username and password. An account keeps your username and permissions across logins. It does not keep a permanent chat archive or sync encryption keys. Passwords are stored as salted hashes, never as plaintext. There is no email recovery, so keep your password safe.
Can I choose which chats notify me?
Open Notifications & account settings in the sidebar. Visual notifications show unread counts in the sidebar and the tab title; they start on for private chats and temporary rooms and off for main rooms. Sounds can be enabled for private chats, temporary groups, main rooms, or any combination, and all start off. Use Test sound if your browser needs permission to play audio. Your choices are saved on this browser.
How do temporary rooms work?
Choose Create beside Temporary rooms. Add a description and rules, and choose Open to everyone or Invite only. Room owners can invite people, kick members, transfer ownership, delete the room, and see each current member’s total messages sent. Open Room details & members to manage the room or verify a member’s identity.
Room text, attachments, and captions are end-to-end encrypted. Use ＋ to attach a photo, GIF, video, audio clip or file, with or without a caption. Names, rules, descriptions, membership, and message counts are visible to the server. New members see only future messages. Kicked sessions cannot rejoin or receive new messages, but may retain copies already received.
Rooms support 20 members and disappear after 24 hours without activity, when empty, or on server restart. Transfer ownership before leaving a room with other members. If you close SilenzaChat or lose your connection for 15 minutes, you leave your temporary rooms automatically. If the owner leaves this way, their session expires or is banned, a moderator or the earliest remaining member becomes owner.

      
How do I start a private chat or send an attachment?
Choose someone under In good company. On a phone, the people list is below the chat. Private conversations appear in the sidebar.
In a private chat or temporary room, use ＋ to choose a file, add an optional caption, then send. Photos (JPEG, PNG, WebP), GIFs, videos (MP4, MOV, WebM) and audio (MP3, M4A, WebM, WAV) are shown in the chat with their metadata removed; images can be up to 64 megapixels. Any other file is offered as a download. Attachments can only be sent in encrypted conversations and can be up to 16 MB unless the host changes this limit. Images load automatically; videos, audio and files are downloaded only when the recipient chooses to load them.

      
What happens if I refresh, clear browser data, or use another device?
Refreshing normally keeps your session and local encryption keys. Tabs in the same browser profile share them. Another browser, browser profile, or device has a separate identity; you can log in with the same account username, but messages, room memberships, and encryption keys do not sync.
Signing in or registering from a guest session starts a separate account identity. It ends the guest’s private conversations and temporary-room memberships and clears their server-held private history and attachments. Previous public posts keep the guest alias.
Clearing site data or ending an incognito session can lose your session and encryption keys. The server cannot recover those keys. If your session remains but its key is lost, private chat is blocked; clear the site’s data to start a new anonymous session.

      
Why is private chat unavailable?
Private chat needs HTTPS, or localhost for local use, and browser storage for encryption keys. Both people need to open the current version of SilenzaChat. If encryption cannot be set up, the app blocks private sending instead of sending plaintext.
If you see an identity-change warning, do not assume it is safe to continue. Contact the other person through a trusted channel. A new anonymous session has a new identity and needs to be verified again.

      
What is stored in my browser?
A session cookie lets the server recognize your anonymous session. Encryption keys and remembered peer identities are stored locally in the browser. Signing out clears current and older private keys and remembered peer identities in this browser, and its other open tabs leave the chat. Key-free revocation markers prevent old identities from being restored. The app also saves your theme and sound preferences. Account usernames, password hashes, and roles are stored on the server. Decrypted messages and unsent drafts stay in the current page’s memory; the app does not save a permanent local chat archive.

      
How do replies, mentions, and moderation work?
Choose Reply on a message to respond to it. Type @ and choose an alias to mention someone. The emoji button opens a searchable picker, and /help lists chat commands.
Admins can edit the name, description, and rules of any user-created room, including invite-only rooms, or delete it. Only the room owner can change access or invite members. They can also ban accounts or guest sessions and remove messages by ID. Those controls do not give them a key to decrypt other people’s private chats. A guest ban affects that browser session. Account bans cover all current sessions and future logins for that account; they cannot prevent someone from creating a different identity.
